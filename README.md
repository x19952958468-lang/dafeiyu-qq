# 大肥鱼 · QQ 聊天与语音助手

通过 NapCat / OneBot 11 连接 QQ，把聊天、人设、点歌、情绪语音和 B站活动接到同一个 Node.js 程序里。

这是从实际运行方案中整理的源码版本。仓库提供代码、测试、配置模板和可选后端接入说明；账号登录态、私人聊天、人设、参考声音、音乐素材、模型权重和虚拟环境不在仓库中。

## 能做什么

| 功能 | 实现与边界 |
| --- | --- |
| 群聊 / 私聊 | @、关键词、引用回复、按配置插话；群白名单、静默和忽略用户 |
| 人设管理 | 网页编辑、保存前备份、即时应用；聊天事实与角色口吻分开处理 |
| 执行动作 | 将点歌、B站查看、主人跨群发言等指令交给功能模块；保留执行结果和上下文 |
| 点歌 | 查找歌曲、提取人声、换声、混音，选取约 20 秒并尽量自然收尾；采用 D 版处理流程 |
| 情绪语音 | Breeze TTS 后端、情绪参考配置、台词与动作描述分离、生成失败回退文字 |
| B站活动 | 扫码登录、字幕 / 语音转写 / 抽帧理解、评论、向绑定 QQ 好友推荐、活动记录回查 |
| 本机后台 | 默认 `http://127.0.0.1:6196/`，管理人设、语音和 B站设置 |

点歌属于基于歌曲素材的换声翻唱，不是仅凭歌名从零创作旋律。约 20 秒是目标时长，实际片段优先选择自然停顿；连续演唱没有合适停顿时会在目标附近淡出，不能保证每次都唱完完整乐段。语音情绪仍受模型、参考音频和台词影响；目前不同台词之间仍可能出现明显的音色漂移，固定种子不能消除这种差异。

## 先启动文字聊天

需要 Node.js **22 或更新版本**、已登录的 NapCat（或兼容的 OneBot 11 正向 WebSocket 服务），以及能调用 `/chat/completions` 的模型接口。Node 主程序没有 npm 第三方运行依赖。

```sh
git clone https://github.com/x19952958468-lang/dafeiyu-qq.git
cd dafeiyu-qq
npm run setup
```

`setup` 创建本地 `config.json` 和 `persona/dafeiyu.md`，已有文件不会覆盖。随后编辑 `config.json`：

1. 填写 `onebot.ws` 与 NapCat 中一致的正向 WebSocket 地址；若协议端设置了访问令牌，填写 `onebot.accessToken`。
2. 填写 `llm.baseUrl`、`llm.apiKey` 和 `llm.model`。示例使用 DeepSeek 兼容接口，也可以换成支持相同请求格式的服务。
3. 把 `whitelist.groups` / `whitelist.friends` 中的占位字符串替换为允许响应的群号 / 好友 QQ，使用字符串数组。
4. 按需要把 `trigger.alwaysReplyMention` 和 `trigger.alwaysReplyPrivate` 改为 `true`，开启群内 @ 回复或私聊回复。

示例默认关闭回复触发、主动插话、入群邀请自动接受和唱歌。**白名单的空数组 `[]` 在现有实现中表示“不限制”，不是“全部禁用”。** 不使用某种会话时保留对应占位项，并保持触发关闭。

```sh
npm test
npm start
```

`npm test` 运行显式列出的离线测试，不连接真实 QQ、不发表评论、不加载模型。`npm start` 会连接配置的 OneBot 服务；用终端的 `Ctrl+C` 停止这个进程。

后台地址：<http://127.0.0.1:6196/>。先测试文字聊天，再按需接入以下模块。

## 接入唱歌、语音和 B站理解

三个模块各自需要额外的 Python 环境、FFmpeg 和模型。具体依赖、下载脚本、启动方法与配置示例见 [可选后端说明](integrations/README.md)。

- **唱歌**：先配置可用的歌曲来源、参考人声及 D 版 worker，再开启 `config.json` 的 `singing.enabled`。歌曲来源或换声失败时不会伪报成功。
- **情绪语音**：准备自己有权使用的参考声音，部署 Breeze 后端，再填写本地 `data/speech/config.json`。网页可调整语音开关、回复比例和情绪强度。
- **B站**：后台选择接收推荐的 QQ 好友，扫码登录后再启用活动。完整的视频理解依赖可选的本地视觉 / 转写后端；只有标题简介时不会宣称完整看过视频。

这些模块共享重计算队列，避免唱歌、语音和视觉模型同时抢占有限内存。模型首次载入和点歌通常比文字回复慢。

## 平台范围

| 环境 | 当前范围 |
| --- | --- |
| macOS / Apple Silicon | 原方案的主要运行环境；可选 MLX 语音和视觉后端按此环境整理 |
| Windows / Linux | Node 主程序使用标准 Node API；QQ 协议端需自行安装。Python、模型和进程管理必须按对应平台适配 |

本次公开整理未在全新 Windows / Linux 环境中完成整套实测，也没有把仓库包装成跨平台一键安装器。Windows 不能直接使用 MLX 后端；Breeze 自动启停脚本目前面向 Unix / macOS。
