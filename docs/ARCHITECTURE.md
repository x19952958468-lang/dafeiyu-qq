# 实现结构

## 消息到回复

```text
QQ / NapCat
    │ OneBot 11 正向 WebSocket
    ▼
Node 主程序
    ├─ 群 / 用户策略、触发与频率判断
    ├─ 会话上下文、引用消息、最近任务记录
    ├─ 指令识别 → 唱歌 / B站 / 主人跨群动作
    └─ 普通聊天 → 模型正文 → 台词检查 → 文字或语音
                                      │
                                      ▼
                              OneBot 发送 + 结果记录
```

`src/index.js` 装配各模块。`src/pipeline.js` 负责消息接入、触发和对话；`src/onebot.js` 负责协议连接；`src/llm.js` 负责模型调用。运行状态保存在本地 `data/`。

## 动作和事实

`src/action-intent.js` 将自然语言请求转成有限的动作结构。`src/actions.js` 分派操作，`src/qq-actions.js` 处理主人授权的跨群发言，`src/action-context.js` 提供最近会话中的候选群上下文。具体模块返回执行结果，聊天层用结果回答进度。

B站模块维护观看、评论、推荐及失败状态。`src/bilibili/conversation.js` 把这些记录接入后续对话，避免用户问“评论了什么”时只得到角色化闲聊。

## 点歌

`src/singing.js` 接收群 @ 或私聊点歌，管理请求、并发和任务状态，通过文件队列交给 Python worker。可选 worker 负责搜索 / 获取音频、分离人声、Seed-VC 换声、处理音色、混音与选段。

保留的是 D 版流程。目标时长约 20 秒，选段考虑乐句边界；歌曲获取质量、原音的人声分离效果和参考声音会共同影响结果。

## 情绪语音

正文生成后，`src/speech/plan.js` 校验台词与叙述的划分。划分必须完整覆盖原文，不能改写、重排或遗漏；不确定时回退文字。语音模块只将确定需要说出口的内容交给 TTS，发送和引用记录也使用实际台词。

`src/speech/emotion.js`、`direction.js` 识别情绪请求，`src/speech/index.js` 选择参考配置、生成、编码并检查音频。`src/speech-backend.js` 管理本进程启动的 Breeze 后端。固定随机种子不能保证不同台词的音色完全一致，这部分仍需根据参考声音调整。

## 视频理解

`src/bilibili/client.js` 负责平台接口和登录。`content.js` 优先读取字幕，并在可用时抽帧、运行本地视觉模型和语音转写。标题简介、字幕、模型描述是不同级别的证据；抽帧不等于完整观看所有画面，自动转写也可能出错。

`service.js` 根据内容和设置决定是否评论、推荐，并写入活动记录。`server.js` 提供本机后台和配置接口。

## 资源调度

`src/heavy-compute.js` 串行协调唱歌、TTS 和视频模型，减少多模型同时占用内存。Node 聊天与后台可以继续处理轻量请求，但重计算会排队，不能承诺固定生成时长。

## 测试边界

仓库测试覆盖解析、白名单、动作分派、队列、B站记录与接口、保存人设、台词分离和语音交付等逻辑。`npm test` 使用显式允许的离线测试列表，并以模拟网络和后端验证行为。

离线测试通过不代表真实 QQ、B站、模型服务或音频听感都已通过验收。登录账号后仍需在自己的测试会话中检查消息投递和生成结果。
