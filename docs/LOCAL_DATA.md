# 本地数据与部署

## 运行文件

| 位置 | 内容 |
| --- | --- |
| `config.json` / `config.local.json` | 模型密钥、OneBot 令牌、群与好友配置 |
| `persona/dafeiyu.md` | 当前使用的人设 |
| `data/` | 会话、登录态、任务、收发记录、预算、音频、后台状态及备份 |
| `work/` | Python 环境、外部源码、模型及工具 |

这些路径默认不进入 Git。公开仓库保留模板、可分发的参考片段和参数，原始私人角色正文不公开；备份上述本地目录时，应使用自己的私有存储。不要把 Cookie、登录二维码、模型密钥或完整聊天日志放入公开 Issue。

## 后台访问

后台绑定 `127.0.0.1`，有请求来源及 CSRF 检查，面向可信的本机用户。它没有供公网多用户部署使用的完整身份认证体系。需要远程访问时，使用自己的受保护隧道；不要直接把后台或 OneBot 端口暴露到公网。

网页保存会改变机器人配置，B站启用后会执行账号操作。初次部署先保持自动活动关闭，填好自己的目标范围，再启用相应模块。

## 启停与升级

在项目目录运行 `npm start`，通过当前终端 `Ctrl+C` 停止。可以自行接入 launchd、systemd 等进程管理器，但应只管理本项目启动的进程。

更新代码前备份本地 `config.json`、`persona/` 和 `data/`，停止机器人后再更新和测试。不要用仓库示例覆盖自己的本地配置。`npm run setup` 只创建缺失文件，不替换已有设置。

## 工具的区别

`npm test` 是离线测试入口。`tools/` 中另有手动查看历史、发送消息、模型预览等操作工具，它们可能读取本地配置、连接真实服务或产生费用。不要用通配符批量执行所有 `tools/*.js`，也不要把所有 `check-*.js` 都当成离线测试。

`npm run doctor` 会尝试连接已配置的模型和 OneBot；若填入真实模型密钥，模型连通性检查会产生一次小请求。它不是无网络的测试命令。

除 [当前预设](../presets/current/README.md) 中获准分发的三段参考录音外，其他音色素材、音乐片段和生成媒体保留在本地。使用自己有权使用的声音和音乐；模型本体及其输出可能适用独立授权。许可入口见 [第三方组件说明](../THIRD_PARTY_NOTICES.md)。
